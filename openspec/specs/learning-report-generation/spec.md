# learning-report-generation Specification

## Purpose

在用户完成一次闯关后，把答题记录复盘为结构化学习报告（正确率、掌握知识点、薄弱知识点、三行总结、学习建议、分享金句），供报告页展示与学习记录持久化使用。

## Requirements

### Requirement: 合法输入下生成完整学习报告

系统必须在答题记录与题目合法（题目与记录一一对应、`question_id` 均存在且不重复、所选选项键合法、记录的 `is_correct` 与所选答案一致）时，通过 `POST /api/v1/report/generate` 返回 `code=0` 与完整报告数据，包含 `accuracy`、`mastered_points`、`weak_points`、`three_line_summary`、`advice`、`share_quote` 六个字段。报告的分析内容必须由 LLM 生成，且获取 LLM 结构化输出的机制必须为模型服务端实际支持的机制；系统不得因结构化输出机制不受服务端支持而使报告生成失败。

#### Scenario: 正常答题完成生成报告
- **WHEN** 已登录或匿名用户提交题目与答题记录完全对应的合法请求
- **THEN** 接口返回完整六字段报告，报告页正常渲染

#### Scenario: 结构化输出机制不受服务端支持时不允许失败
- **WHEN** 模型服务端不支持某类结构化输出约束（如服务端 JSON Schema 强约束）
- **THEN** 系统改用服务端支持的等价机制完成结构化输出，接口仍返回完整报告，而不是将服务端 400 错误透传为生成失败

#### Scenario: 升级后行为不回退
- **WHEN** LLM 相关依赖升级导致结构化输出的默认行为发生变化
- **THEN** 回归测试断言报告链路显式声明所用的结构化输出方式，报告生成不因默认值漂移而失败

### Requirement: 正确率由后端确定性计算

返回的 `accuracy` 必须由后端按答题记录中 `is_correct` 的比例计算并四舍五入为整数百分比，不得采信模型输出的 `accuracy` 字段。

#### Scenario: 模型统计与实际不符时以后端为准
- **WHEN** 模型返回的 `accuracy` 与后端按答题记录统计的结果不一致
- **THEN** 接口返回后端统计的 `accuracy`

### Requirement: 全对与全错边界照常生成

答题记录全部正确时，薄弱知识点列表允许为空；答题记录全部错误时，掌握知识点列表允许为空。这两种边界下报告必须照常生成成功，其余字段（三行总结、学习建议、分享金句）仍必须满足各自的结构约束。

#### Scenario: 全部答对
- **WHEN** 用户本次答题记录全部正确
- **THEN** 报告照常生成，`weak_points` 允许为空列表，接口不返回错误

#### Scenario: 全部答错
- **WHEN** 用户本次答题记录全部错误
- **THEN** 报告照常生成，`mastered_points` 允许为空列表，接口不返回错误

### Requirement: 非法输入与不合规模型输出返回业务错误

请求校验失败（缺少 `quiz_id` 或主题、题目或记录为空、题目与记录数量不一致、`question_id` 不存在或重复作答、所选选项键非法、`is_correct` 与所选答案不符）或模型输出违反报告结构约束（`accuracy` 越界、三行总结不为恰好 3 条、学习建议为空、分享金句为空或超过 100 字）时，系统必须返回携带中文可读提示的业务错误，不得以未处理异常或 500 响应。

#### Scenario: 正确性与所选项不符
- **WHEN** 某条答题记录的 `is_correct` 与其 `selected_answers` 推导出的判定结果不一致
- **THEN** 接口返回业务错误与中文提示，不产生报告

#### Scenario: 模型输出缺三行总结
- **WHEN** 模型返回的报告结构中三行总结不是恰好 3 条
- **THEN** 接口返回业务错误与中文提示，不将不合规格式的报告返回给前端
